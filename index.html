How to use INKFORGE

The whole process, start to finish. Tap a step to open it. You stay in charge: nothing is final until you approve it.

1. First-time setup
  1. Pen names: add a name and its voice notes. Series: add a series under that pen name. Books: add a book in the series.
  2. Story Studio: start a brief for the book and fill every field marked “required”, then tap Approve brief. Chapters can’t be added until a brief is approved. To change it later, tap Start new version.
  3. Series Bible: propose facts that must never change (names, ages, places, relationships), then tap Approve as canon. To change approved canon, propose a replacement and pick the entry it replaces. After a chapter is written, tap Propose canon on it: the AI proposes entries from the text, which you approve or reject here.
  4. Settings: paste your Gemini key and tap Save AI settings. Tap Test connection and list models, tap a model, then Send test message. Finally switch off both kill switch and No-AI mode.
2. Plan the chapters (outline)
  1. Books → open the book → AI outline. Start with 2 to 3 chapters; bigger requests can time out. AI Tasks shows how long each call took, which tells you your own limit. Tap Generate outline.
  2. Open AI Tasks. When it says done, tap Apply outline. Nothing is added until you do.
  3. Back in the book, read each chapter’s Outline box and edit it by hand. Tap Save version to keep your edits.
  4. If the book already has chapters, the new outline continues after them and uses your accepted Book State.
3. Write a chapter
  1. On the chapter, tap AI draft and wait (up to a few minutes).
  2. Tap Use draft. Your previous text is kept as a version. Read it, edit it, tap Save version.
  3. The small line under the outline shows what the draft was built from (brief, canon facts, state entries).
4. Check and approve a chapter
  1. Tap Extract state. Then open Book State: Accept what’s true, Reject what’s wrong, edit then Save correction to sharpen, and use Add entry for feelings or secrets it missed. Only accepted entries feed later chapters.
  2. On the chapter, pick a scope (start with continuity) and tap Run check.
  3. For each finding: Accept if real, Dismiss if wrong or just a preference, Escalate if unsure. Apply fix replaces only the quoted passage. Resolve when handled.
  4. Tap Submit for review, then Approve. Approving locks the chapter; use Reopen for edits to change it. It can’t be approved while a high-severity finding is open.
5. Next chapters
  1. Before each new chapter, make sure the earlier one is approved, its state is reviewed, and the canon is up to date.
  2. On the new chapter’s outline, tap Check against story so far. It compares the outline with canon, accepted Book State and earlier chapters. Fix or dismiss each finding.
  3. Then tap AI draft and repeat steps 3 and 4. After using the draft, run the same check again on the finished text.
  4. Settings has an option to run this check automatically after an outline or draft. It uses extra calls.
6. Finish the whole book
  1. When every chapter is approved, tap Run manuscript audit in the book and handle its findings the same way.
  2. Tap Send to quality check. Fix anything in red.
  3. Tap Approve manuscript. If editorial readiness isn’t met you can Approve with override; the override is recorded.
  4. Show export gives Markdown to copy out. Unapproved books are watermarked.
7. Keep your work safe
  • Settings → Show backup JSON → copy it somewhere outside the app. Do this after each approved chapter.
  • To restore: paste the backup into the box and tap Restore from box. Your API key is never in a backup.
  • Never clear site data or storage for this app. That erases your book.
  • To update the app: replace the files in your GitHub repo, then close and reopen the app. Your data stays. Settings shows the build label so you can confirm.
8. If something goes wrong
  • Failed to fetch / unreachable: tap Send test message in Settings. Try the other network (Wi-Fi or mobile data). Try the Streaming checkbox on or off.
  • No reply in N s: use fewer chapters, or raise the timeout in Settings.
  • HTTP 404: wrong model. Use Test connection and pick one from the list.
  • HTTP 403: key rejected or restricted. HTTP 429: quota hit; the app pauses for 10 minutes.
  • Invalid response: the model replied in the wrong format. Tap Run again.
  • “AI unavailable” in AI Tasks: it tells you why (kill switch, No-AI mode, no key, daily limit, cooldown).
  • Can’t add a chapter: approve the brief first. Can’t approve: it names what’s blocking; usually an open high-severity finding.
9. Costs and limits
  • Every AI task is one or more calls. The daily limit in Settings caps them; free quota from Google is unknown, so check your Google account.
  • The app never switches to a paid service by itself. The kill switch stops all AI calls instantly.
  • AI Tasks shows tokens reported by Google separately from the app’s own estimates.
